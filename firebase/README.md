# Firestore setup

投稿機能は Firebase Authentication と Firestore を使います。

1. Firebase Console でプロジェクト `help5-d7f86` を開く。
2. **Firestore Database** を作成する。
3. **ルール** タブを開き、`firestore.rules` の内容を貼り付けて公開する。

`helpPosts` コレクションはログイン済みの本人として投稿します。投稿者以外の1人が「助けに行く」を選ぶと、担当者として登録されます。

## チャット

「助けに行く」の保存成功後、`/help/:id/chat` を開きます。投稿者・担当者は「メッセージ」一覧や投稿詳細の「チャットを開く」から同じ会話を開けます。チャット内の「詳細・地図」から地図案内へ戻れます。

メッセージは `helpPosts/{postId}/messages/{messageId}` に `senderUid`・`text`・`createdAt` を保存し、Firestore の購読で受信します。会話は投稿単位なので、開き直しても同じ履歴になります。最初の送信前はメッセージが0件です。投稿が削除されると、その会話は一覧から消え、履歴へのアクセスも禁止されます。

### Firebase側に反映すること

コードを更新しただけでは既存のFirestoreルールは変わりません。Firebase Console の **Firestore Database → ルール** で、このフォルダの `firestore.rules` 全体を反映してください。旧ルールのままでは、チャットの読み書きが拒否されます。

ルールでは、担当者が決まった投稿の当事者2人だけに閲覧を許可します。送信は `matched` の間だけ許可し、送信者UID・サーバー時刻・1〜2000文字の本文を検証します。解決後は履歴の閲覧のみ可能で、送信済みメッセージの編集・削除はできません。

### 確認手順

1. アカウントAで投稿し、別ブラウザのアカウントBで「助けに行く」を押す。Bのチャットが開くことを確認する。
2. Aの「メッセージ」一覧に会話が現れることを確認する。A・B双方から送信し、相手の画面に届くことを確認する。
3. 再読み込み・一覧からの再入室で履歴が残り、新しい別の会話が作られないことを確認する。
4. 日本語変換確定のEnterでは送信されず、空白だけの本文や連打で重複送信されないことを確認する。
5. 「詳細・地図」から位置情報とルート案内が引き続き使えることを確認する。
6. 無関係なアカウントCで同じチャットURLを開いても履歴を読めないことを確認する。ルールのテストでは未認証アクセス・第三者の直接読み書き・送信者UIDの偽装・2000文字を超える本文・メッセージ編集も拒否されることを確認する。
7. Aのマイページから投稿を解決済みにし、A・Bが履歴を読める一方で新規送信できなくなることを確認する。

担当者の表示名はまだ保存していないため、投稿者側では相手を「助けに向かう人」と表示します。一覧には最新メッセージではなく投稿タイトルを表示し、担当者が決まった日時の新しい順に並べます。
